# Самостоятельная работа: восстановление сейсмических кубов

Срок сдачи — 29.11.2026 включительно. Основное описание задания находится в `slides.md`, пример оформления — в `TEMPLATE_independent_work_result.ipynb`.

Решение содержит отдельные ноутбуки для inpainting и outpainting. Обучение использует только соответствующий входной куб, без сторонних данных.

## Окружение и запуск

Для Windows:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
jupyter notebook
```

Для Linux и macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
jupyter notebook
```

Скачайте данные по [ссылке](https://disk.yandex.ru/d/JRT1Q5WP3NzGMQ) и разместите файлы так:

```text
input_seismic_data/
├── inpainting_cube_missed_data.npy
└── outpainting_cube_missed_data.npy
```

Откройте `inpainting.ipynb` или `outpainting.ipynb` и последовательно выполните все ячейки. Ноутбук проверит SHA-256, форму куба и расположение пропусков до начала обучения. Для продолжения обучения с лучшего чекпоинта той же конфигурации установите `RESUME = True` в блоке настройки обучения и повторно запустите ячейки обучения. После смены последовательной оси на `x` и перехода к шести входным каналам inpainting требуется полное переобучение: старые веса несовместимы с текущей моделью.

В обеих задачах validation и test выполняются в causal-режиме с холодным стартом и собственными предсказаниями в прошлых каналах, без ground truth. R считается внутри каждого x-среза; в outpainting дополнительно отдельно для верхней и нижней полосы. Это исключает завышение метрики из-за разных средних и масштабов. На test обеих задач выводятся MAE и RMSE: Pearson не наказывает за линейную ошибку амплитуды и смещения.

## Текущая конфигурация

- Inpainting использует исходную ориентацию `(x, y, z) = (580, 951, 462)`, патчи `304×144` и целевую маску `213×103` в плоскости `(y, z)`. Выполняются 580 последовательных восстановлений от `x=0` до `x=579`. Модель получает 6 каналов: пять срезов `x±2` и маску. Предсказания записываются в рабочий куб и используются каналами `x−2` и `x−1`; на `x=1` оба канала содержат предсказание `x=0`.
- Outpainting использует куб `(460, 481, 800)`, патчи `368×256` и две полосы шириной 24. Основной инференс выполняет 460 causal-шагов по `x`, восстанавливая обе полосы на каждом срезе и используя собственные предсказания в каналах `x−2` и `x−1`. `restore_volume(causal=False)` сохраняет независимый baseline.
- В обоих ноутбуках `base_channels = 24`, в bottleneck добавлены свёртки с dilation 2 и 4. Модель оборачивается в `torch.compile`, выполняется warmup с backward, чекпоинты сохраняются из `raw_model`.
- Inpainting: `BATCH_SIZE = 24`, `EPOCHS = 100`, `BASE_LR = 1e-3`, `L1_WEIGHT = 0.3`, `GRAD_LOSS_WEIGHT = 0.3`, `STD_LOSS_WEIGHT = 0.05`, `FFL_WEIGHT = 0.05`, warmup 5 эпох, `RUN_NAME = "sequential-x-causal"`; `ReduceLROnPlateau(mode="max", factor=0.5, patience=4, min_lr=1e-5)` уменьшает LR по validation R.
- Размеры датасета inpainting: train — 3521 пример (503 x-центра × 7), validation — 92 предсказания (2 трека × 46), test — 46 (2 трека × 23). Validation и test используют held-out блок `y=77:290`, `z=179:282` (213×103 на x-срезе), холодный старт и последовательные предсказания без настоящих прошлых срезов. Обучающие патчи не пересекают held-out или реальный пропуск. `TRAIN_SAMPLES_PER_CENTER` задаёт число случайных примеров на центральный x-срез за эпоху.
- Outpainting: `BATCH_SIZE = 16`, `EPOCHS = 75`, `BASE_LR = 2e-3`, `GRAD_LOSS_WEIGHT = 0.3`, `STD_LOSS_WEIGHT = 0.05`, `FFL_WEIGHT = 0.05`, `RUN_NAME = "sequential-x-causal"`; используется `ReduceLROnPlateau(patience=4, factor=0.5)`. Train — 1280 примеров, validation — 140 предсказаний (2 трека × 70), test — 116 (2 трека × 58).
- Потери обеих задач включают L1, MSE, gradient L1, STD-loss с весом `0.05`, FFL по всем частотам с весом `0.05` и `0.5 · (1 − R)`. В outpainting STD и R вычисляются отдельно для каждой полосы. FFL использует спектр `rfft2((pred − target) · mask, norm="ortho")` и линейный warmup 5 эпох. На test применяется полный вес. Норма градиентов не вычисляется.
- В 75% train-батчей обеих задач выполняется один шаг, в 25% — rollout длиной 3 с подачей прошлых предсказаний через `detach()` в каналы `x−2` и `x−1`. Это даёт в среднем 1,5 forward/backward на батч. В 10% батчей прошлые каналы первого шага маскируются для обучения холодному старту. R вычисляется векторно через маскированные моменты, без Python-цикла по срезам и без синхронизации GPU внутри эпохи.
- Положение патчей и масштаб амплитуд остаются динамическими. Отражения по `y` и `z` не меняют направление последовательного восстановления по `x`. Gaussian noise предрассчитывается перед обучением в банк из 64 вариантов. Нормализация использует только train-срезы.
- Все блоки внимания заменены на универсальный `TokenAttention`: токенизация через `Conv2d`, размерность токена 128, 4 головы. На 1/16 полное внимание использует 171 токен; на 1/8, 1/4 и 1/2 — 171, 684 и 2736 токенов. В decoder query создаются только для центральных 20% пропуска (3, 15 и 55 query), которые обращаются ко всем key/value своего масштаба. Крайние токены не участвуют в attention. Обратное преобразование выполняется через `ConvTranspose2d`, блок добавляет результат к входу через residual.
- Для ablation без gradient loss установите `GRAD_LOSS_WEIGHT = 0.0` и `RUN_NAME = "no-grad-l1"`, сохранив остальные параметры.

Выходы ячеек очищены, поскольку прежние результаты относились к другим конфигурациям.
