# CV_project — восстановление сейсмических кубов

Студенческое задание: `inpainting` (внутренняя область пропусков) и `outpainting` (граничные полосы) куба сейсмических данных с помощью 2.5D U-Net.

## Структура
- `inpainting.ipynb` / `outpainting.ipynb` — рабочие ноутбуки, одинаковая структура блоков: окружение → данные (SHA-256 + проверка нулей) → модель → обучение → тестирование → инференс → сохранение артефактов.
- `seismic_dataset.py` — геометрия патчей/масок, последовательные примеры inpainting в ориентации `(x, y, z)`, генераторы примеров и классы датасетов обоих задач; датасеты живут в модуле, а не в клетках (spawn-воркеры DataLoader не импортируют классы, определённые в Jupyter-клетках).
- `0_seismic.ipynb`, `TEMPLATE_independent_work_result.ipynb`, `SeismicUtils.py`, `slides.md` — исходные материалы и шаблоны.
- `requirements.txt` — зависимости (torch, numpy, matplotlib, tensorboard, jupyter, tqdm, mlflow).
- `whl/` — офлайн-копии всех нужных wheels (182 пакета, версии соответствуют `.venv`), для офлайн-установки в вычислительном окружении.
- `inference/` — локальный просмотрщик восстановленных кубов (serve.py + index.html), см. «Inference viewer».

## Конвенции
- Ноутбуки — JSON c `indent=1`, `ensure_ascii=False`, `source` ячейки = массив по одной строке (со своим завершающим `\n`). Править через скрипт (json.load → правка `source` → json.dump в том же формате + завершающая `\n`), не править руками.
- Прогресс обучения — tqdm: внешняя полоса по эпохам со `set_postfix` (train всегда, val на эпохах валидации), вложенные полосы `tqdm(loader, desc="train"/"val", leave=False)`; print в блоке обучения нет.
- Оба ноутбука: matplotlib принудительно в бэкенде `Agg` — `plt.show()` в вычислительном окружении зависает; все визуализации (тестовые примеры, восстановленные срезы, история обучения) — статические PNG (`fig.savefig` + `display(Image(...))`); plotly и ipywidgets удалены из ноутбуков и `requirements.txt` (JS от `fig.show()` и виджеты `ipywidgets` в фронтенде не рендерятся — клетка с слайдером зависала в бесконечном выполнении). Вместо слайдера — статическая клетка `*-restored-slices`: сетка 4 среза × 3 панели → `*_restored_slices.png`; `show_restored_slice(N)` (объект `slice_panels` — общее построение панелей одного среза) осталась для ручного просмотра конкретного среза. Прогресс — классический `from tqdm import tqdm`.
- Общие настройки обучения: `NUM_WORKERS = 0`, `persistent_workers = NUM_WORKERS > 0`, train `DataLoader` обоих ноутбуков получает `worker_init_fn=seed_worker`, `VALIDATION_EVERY = 1`, `R_LOSS_WEIGHT = 0.5`. AMP — нативный bf16, веса модели и оптимизатора остаются fp32. В циклах нет `.item()` до конца эпохи. Потеря inpainting = `L1 + MSE + w_grad·∇L1 + w_std·STD + w_ffl·FFL + 0.5·(1 − R)`. STD-loss сравнивает std предсказания и target внутри маски каждого среза с `STD_LOSS_WEIGHT = 0.05`. В inpainting FFL использует все частоты, в outpainting — высокие с `FFL_HF_CUTOFF = 0.25`; `FFL_WEIGHT = 0.05`, линейный warmup 5 эпох, на test полный вес. High-frequency (Sobel/Laplacian) не используется. Норма градиентов не вычисляется и не логируется.
- Inpainting: `BATCH_SIZE = 24`, `EPOCHS = 100`, `EARLY_STOPPING_PATIENCE = 24`, `L1_WEIGHT = 0.3`, `GRAD_LOSS_WEIGHT = 0.3`, `STD_LOSS_WEIGHT = 0.05`, `FFL_WEIGHT = 0.05`, warmup 5 эпох, `ROLLOUT_STEPS = 3`, `ROLLOUT_BATCH_PROBABILITY = 0.25`, `RUN_NAME = "sequential-x-causal"`; AdamW начинает с `BASE_LR = 1e-3`, `ReduceLROnPlateau(mode="max", factor=0.5, patience=4, min_lr=1e-5)` получает validation R после каждой валидации. Модель: `model = torch.compile(model)` в ячейке training-setup; JIT-компиляция выполняется в `inpainting-compile-warmup` — dummy-батч `[BATCH_SIZE, 6, PATCH_H, PATCH_W]` с каналом маски=1, forward + `backward()` в том же autocast. Входные каналы — пять x-срезов `center±2` и маска текущего среза; всего 6 каналов, маска находится в канале 5. Патч имеет форму `304×144`, целевая маска — `213×103`.
- Outpainting: `BATCH_SIZE = 16`, `EPOCHS = 75`, `EARLY_STOPPING_PATIENCE = 12`, `GRAD_LOSS_WEIGHT = 0.3`, `FFL_WEIGHT = 0.05`, `RUN_NAME = "gradient-l1-ffl"`; AdamW `lr = 2e-3` + `ReduceLROnPlateau(mode="max", factor=0.5, patience=4, min_lr=1e-5)`.
- Все блоки внимания inpainting объединены в `TokenAttention`: `Conv2d` создаёт токены размерности 128, используются 4 головы и нулевая инициализация выходной проекции. На 1/16 после bottleneck выполняется полное внимание по 171 токену. На 1/8, 1/4 и 1/2 после соответствующих ступеней декодера используются 171, 684 и 2736 токенов; маска уменьшается тем же pooling, query создаются только для центральных 20% пропуска (3, 15 и 55 query) и обращаются ко всем key/value своего масштаба. Крайние токены не участвуют в attention и не получают обновлений. `ConvTranspose2d` восстанавливает пространственную карту, результат добавляется через residual. Чекпоинт сохраняется из `raw_model = model._orig_mod`, чтобы его можно было загрузить в обычный `UNet25D` без префиксов `torch.compile`; warmup синхронизирует CUDA только на CUDA-устройстве.
- В `inpainting.ipynb` R — средний Pearson внутри каждого среза: `masked_r` векторно считает корреляцию только по маске каждого примера и усредняет по батчу без Python-цикла по срезам; train/val/test усредняют её по числу примеров. Тот же per-slice R используется в R-loss. Глобальное объединение срезов запрещено: разные средние и масштабы срезов завышают R. В `outpainting.ipynb` остаётся глобальный Pearson через моменты.
- Аугментация только для train: положение патча, отражения по `y` и `z` и масштаб амплитуд генерируются динамически; отражения не меняют последовательную ось `x`. Gaussian noise предрассчитывается при создании train-датасета в банк `NOISE_BANK_SIZE = 64`; пример использует шум по `index % 64`. `TRAIN_SAMPLES_PER_CENTER`: inpainting = 7, outpainting = 4; для inpainting заданы `VAL_ROLLOUT_TRACKS = 2` и `TEST_ROLLOUT_TRACKS = 2`, геометрия каждой последовательности фиксирована.
- MLflow-трекинг в обоих ноутбуках: логируются параметры, LR, R и взвешенные вклады L1, MSE, R, STD, gradient и FFL. Gradient norm и high-frequency удалены из логов. TensorBoard использует `runs/<task>/<timestamp>`, тест сохраняет модель через MLflow и завершает run.
- Held-out блок inpainting: `HELD_OUT_BOX = (77, 290, 179, 282)` в плоскости `(y, z)` (213×103 на x-срезе) исключён из train и как target, и как input; нормализация также исключает held-out и реальный пропуск. Validation и test (`held_out=True`) используют этот блок. Положение патча варьируется через `mask_y=16:75`, `mask_z=16:25`; на реальном инференсе `mask_y=45`, `mask_z=20`. В 75% train-батчей выполняется один шаг, в 25% — rollout длиной 3 по `x`: прошлые предсказания подаются через `detach()` в каналы `x−2` и `x−1`, включая случай дублированного `x=0` на границе. Среднее число forward/backward на батч — 1,5. С вероятностью `COLD_START_PROBABILITY = 0.1` прошлые каналы первого шага дополнительно маскируются внутри target-области. Validation и test используют `fixed_start=True`, локальные `prediction_sources(0, steps)` и холодный старт: validation — 2 трека по 46 шагов, test — 2 трека по 23 шага. Ground truth в прошлых каналах не используется, поэтому R и выбор лучшего чекпоинта учитывают накопление ошибки.
- Разбиение: `inpainting.ipynb` — доли `TRAIN_RATIO`/`VAL_RATIO`/`TEST_RATIO = 0.88/0.08/0.04`, `SPLIT_GAP = 4`, `SLICE_RANGE = (0, 580)` по оси `x`; 503/46/23 центров и 3521/92/46 примеров для train/val/test; `outpainting.ipynb` — фиксированные центры (train 2–321, val 326–395, test 400–457) с защитными зазорами.
- Куб в обоих ноутбуках предзагружен в оперативную память (`np.load(DATA_PATH)`) вместо mmap: копирование патчей в датасете быстрее.
- В блоке тестирования обоих ноутбуков первая клетка загружает модель `UNet25D().to(device)` из чекпоинта (`best_inpainting_unet.pt` / `best_outpainting_unet.pt`): метрики и примеры предсказаний считаются на лучшей по валидационному R модели, а не на последней эпохе обучения. Inpainting логирует per-slice `test_r`, а также `test_mae` и `test_rmse` по всем маскированным значениям; outpainting использует глобальный `test_r`.
- Инференс inpainting последовательный в исходной ориентации `(x, y, z)`: 580 шагов от `x=0` до `x=579`. Патч `304×144` располагается в `y=323:627`, `z=159:303`, маска имеет размер `213×103`. Модель получает пять кадров `x±2` и маску; несуществующие индексы дублируют ближайший срез. На `x=0` прошлые каналы маскируются, на `x=1` оба содержат предсказание `x=0`, далее — предсказания `x−2` и `x−1`. Текущий и будущие кадры маскируются внутри реального пропуска. Предсказание сразу записывается в рабочий куб и используется следующими вызовами. Визуализация читает готовый `restored_cube`; сохранение выполняется без транспонирования. Outpainting по-прежнему применяется к полному исходному срезу независимо.
- Детерминизм: `SEED=42` (random/np/torch/cuda). Оба ноутбука недетерминированы: `torch.backends.cudnn.benchmark = True` без `use_deterministic_algorithms` (разбег метрик между запусками ~1e-3); детерминизм `outpainting.ipynb` (`CUBLAS_WORKSPACE_CONFIG=:4096:8` + `use_deterministic_algorithms`) снят.

## Inference viewer
- `inference/serve.py` — автономный HTTP-сервер (stdlib + numpy, без других зависимостей): `python inference/serve.py --port N` → `http://127.0.0.1:N` (пути закреплены к корню проекта, не зависят от cwd). Автоскан `output/*/<task>_cube_restored.npy` (manifest живой — новые кубы появляются после обновления страницы без перезапуска). В RAM одновременно один куб (новый высвобождает старый, загрузка ~1–3 с); эндпоинты: `/` (index.html, читается с диска на каждый запрос), `/manifest` (JSON `{"cubes": [...]}`: shape, коробки пропусков, missed axis), `/slice?sub&task&axis&i` (uint8-плоскость, квантование p1–p99 по известным значениям куба). В manifest, кроме восстановленных, всегда два исходных куба `input_seismic_data/{inpainting,outpainting}_cube_missed_data.npy` (метка `label: «исходный»`, те же boxes/missed axis); серверятся через тот же `/slice` (в RAM по-прежнему один куб, исходные и восстановленные вытесняют друг друга).
- `inference/index.html` — просмотрчик: селектор куба (подпапка + задача), селектор оси (по умолчанию «ось пропусков»: inpainting→0, outpainting→1), слайдер среза (при смене оси/куба позиция сбрасывается туда, где пропуски видны: 0, если 0 внутри области пропусков, иначе середина первого интервала пропусков по оси), одна панель «Результат» (крупно) + подписи размерностей осей (ось K · M); область пропусков обведена красным контуром, в исходных кубах поверх — полупрозрачная подложка + штриховка + подпись «нет данных» (ноль пропусков квантуется в чёрный и сливался с фоном, поэтому выделен явно); пиксели панели записываются как `plane[x*h + y]` (x — ось `dims[0]`, y — ось `dims[1]`): прямое плоское копирование `plane[p]` давало сдвинутый (sheared) срез при различном размере двух осей; в селекторе кубов два «исходных» из `input_seismic_data` (в них пропуски нулевые — сравнение с результатом). Области пропусков заданы жёстко в `serve.py` (`TASKS`): inpainting `[:, 368:581, 179:282]`, outpainting `[:, 0:24, :]` + `[:, 457:481, :]`.
- `inference/README.md` — как запускать.

## Запуск и проверка
- Ноутбуки требуют входной `.npy` из `input_seismic_data/` и torch; вычислительное окружение — проект: `.venv` с torch 2.15.0+cu134 (CUDA, bf16), `python = .venv\Scripts\python.exe`; `torch.compile` требует triton — в venv стоит Windows-сборка `triton-windows` 3.9.0.post30 (wheel зеркалирован в `whl/`, офлайн-установка из `C:/Dev/offline_packages`).
- Скрипты проверки JSON/синтаксиса ячеек пишутся во временные `tmp_*.py` и удаляются после проверки.
- В кубах пропуски хранятся как 0 (NaN нет), поэтому проверка односторонняя: «область пропусков заполнена нулями». Вне области есть естественные нули (inpainting: 1 в (451, 363, 437), outpainting: 73), поэтому строгое сравнение `cube == 0` с маской не используется.
- `real_mask` строится in-place: 3D `np.zeros(cube.shape, dtype=bool)` — inpainting исходно `[:, 368:581, 179:282]`, outpainting полосы `0:24` и `457:481`; маски из `.npy` не читаются. Inpainting оставляет куб и маску в исходной ориентации `(x, y, z)`, где пропуск — `[:, 368:581, 179:282]`. Геометрический кросс-чек инференса проверяет, что одна и та же область `(y, z)` пропущена на всех 580 x-срезах.
