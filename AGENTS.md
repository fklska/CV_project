# CV_project — восстановление сейсмических кубов

Студенческое задание: `inpainting` (внутренняя область пропусков) и `outpainting` (граничные полосы) куба сейсмических данных с помощью 2.5D U-Net.

## Структура
- `inpainting.ipynb` / `outpainting.ipynb` — рабочие ноутбуки, одинаковая структура блоков: окружение → данные (SHA-256 + проверка нулей) → модель → обучение → тестирование → инференс → сохранение артефактов.
- `seismic_dataset.py` — константы геометрии патчей/масок, генераторы примеров и классы датасетов обоих задач; датасеты живут в модуле, а не в клетках (spawn-воркеры DataLoader не импортируют классы, определённые в Jupyter-клетках).
- `0_seismic.ipynb`, `TEMPLATE_independent_work_result.ipynb`, `SeismicUtils.py`, `slides.md` — исходные материалы и шаблоны.
- `requirements.txt` — зависимости (torch, numpy, matplotlib, tensorboard, jupyter, tqdm, mlflow).
- `whl/` — офлайн-копии всех нужных wheels (182 пакета, версии соответствуют `.venv`), для офлайн-установки в вычислительном окружении.
- `inference/` — локальный просмотрщик восстановленных кубов (serve.py + index.html), см. «Inference viewer».

## Конвенции
- Ноутбуки — JSON c `indent=1`, `ensure_ascii=False`, `source` ячейки = массив по одной строке (со своим завершающим `\n`). Править через скрипт (json.load → правка `source` → json.dump в том же формате + завершающая `\n`), не править руками.
- Прогресс обучения — tqdm: внешняя полоса по эпохам со `set_postfix` (train всегда, val на эпохах валидации), вложенные полосы `tqdm(loader, desc="train"/"val", leave=False)`; print в блоке обучения нет.
- Оба ноутбука: matplotlib принудительно в бэкенде `Agg` — `plt.show()` в вычислительном окружении зависает; все визуализации (тестовые примеры, восстановленные срезы, история обучения) — статические PNG (`fig.savefig` + `display(Image(...))`); plotly и ipywidgets удалены из ноутбуков и `requirements.txt` (JS от `fig.show()` и виджеты `ipywidgets` в фронтенде не рендерятся — клетка с слайдером зависала в бесконечном выполнении). Вместо слайдера — статическая клетка `*-restored-slices`: сетка 4 среза × 3 панели → `*_restored_slices.png`; `show_restored_slice(N)` (объект `slice_panels` — общее построение панелей одного среза) осталась для ручного просмотра конкретного среза. Прогресс — классический `from tqdm import tqdm`.
- Общие настройки обучения: `NUM_WORKERS = 0`, `persistent_workers = NUM_WORKERS > 0`, train `DataLoader` обоих ноутбуков получает `worker_init_fn=seed_worker` (из `seismic_dataset.py`: `dataset.rng = default_rng(worker_info.seed)`), иначе при `NUM_WORKERS > 0` все воркеры унаследуют одинаковое состояние RNG и выдадут дубли, `VALIDATION_EVERY = 1`, `R_LOSS_WEIGHT = 0.5`. AMP — нативный bf16, веса модели и оптимизатора остаются fp32. В циклах нет `.item()` до конца эпохи. Потеря = `L1 + MSE + w_grad·∇L1 + w_FFL·FFL + 0.5·(1 − R)`; FFL — focal frequency loss только по высоким частотам: `rfft2((pred − target)·mask, norm="ortho")` в float32 вне autocast, спектр умножается на полосу `clamp((ρ − FFL_HF_CUTOFF)/(1 − FFL_HF_CUTOFF), 0, 1)` (ρ — нормированный радиус частоты, 1 = угол спектра), focal-вес `|Δ|/max|Δ|` считается внутри полосы, штраф `weight·|Δ|²`. В обоих ноутбуках `FFL_WEIGHT = 0.05`, `FFL_HF_CUTOFF = 0.25`, вес линейно растёт за `FFL_WARMUP_EPOCHS = 5` и логируется (`Weights/FFL`, `ffl_weight`); на test применяется полный вес. High-frequency (Sobel/Laplacian) и Fourier-L1 не используются. Норма градиентов не вычисляется и не логируется.
- Inpainting: `BATCH_SIZE = 24`, `EPOCHS = 100`, `EARLY_STOPPING_PATIENCE = 24`, `L1_WEIGHT = 0.85`, `GRAD_LOSS_WEIGHT = 0.75`, `FFL_WEIGHT = 0.05`, `RUN_NAME = "block-attn-ffl"`; 3 эпохи warmup до `BASE_LR = 2e-3` + cosine до `MIN_LR = 1e-5`. Модель: `model = torch.compile(model)` в ячейке training-setup (компилируется только модель, потеря с FFL остаётся eager); JIT-компиляция тритон-кернелов сдвинута в отдельную ячейку `inpainting-compile-warmup` после training-setup — dummy-батч `[BATCH_SIZE, 6, PATCH_H, PATCH_W]` с каналом маски=1, forward + `backward()` в том же autocast, так что первая эпоха не платит за компиляцию.
- Outpainting: `BATCH_SIZE = 16`, `EPOCHS = 75`, `EARLY_STOPPING_PATIENCE = 12`, `GRAD_LOSS_WEIGHT = 0.3`, `FFL_WEIGHT = 0.05`, `RUN_NAME = "gradient-l1-ffl"`; AdamW `lr = 2e-3` + `ReduceLROnPlateau(mode="max", factor=0.5, patience=4, min_lr=1e-5)`.
- Патчи: inpainting 304×144 с дырой 213×103 (21 837 известных и 21 939 восстанавливаемых пикселей), outpainting 368×256. В обоих ноутбуках `base_channels = 24`, bottleneck содержит dilation 2 и 4. `RingAttention` работает на 48 каналах с 4 головами по 12: постоянная локальная геометрия маски 107×52 соответствует дыре 213×103; query объединяются в блоки 2×2 (усреднение query-проекции, окно блоков 54×26), первые 35 пикселей исходной дыры исключены из query. Фиксированные радиальные зоны: центральная (10% размеров дыры, 6×2 блока) — все попиксельные key/value окна 115×60 (6900 позиций: дыра + кольцо шириной 4); остальные 268 блоков — только внешнее кольцо (1336 позиций). Вес выхода attention кусочно-постоянный: центр 1.0, средняя зона (радиус ≤ 0.5) 0.75, внешняя 0.25; блочный выход возвращается на 2×2 пикселя ближайшим соседом. К логитам добавляется обучаемый относительный bias `bias_y[head, 2·(fy − qy)] + bias_x[head, 2·(fx − qx)]` (центр query-блока и ключ в системе координат дыры; таблицы инициализированы нулями). Позиция маски находится батчево через `argmax`; gather и два вызова явного attention (центр / периферия; не SDPA, т. к. нужен обучаемый bias) обрабатывают весь батч без цикла и `nonzero()`. qkv считается на `x` с нулевым padding `ring_width` (4 px) по всем сторонам: окна query, кольцо key/value и финальный `scatter` обновлений работают в паддингованных координатах, кольцо, выходящее за границу патча, заполняется нулями, а обновления обрезаются обратно в `h×w` — без этого индексы `gather`/`scatter` уходили за границы (отрицательные при `top < 4`, `top + 107 ≥ 152` у нижнего края), что триггерит device-side assert и в eager, и в `torch.compile`, в том числе на всеединичной маске compile-прогрева. Дополнительно `GlobalAttention` (полный self-attention по всем токенам, depthwise 3×3 как позиционный сигнал, нулевая инициализация проекции) стоит на 1/16 после bottleneck (384 канала, 8 голов, 19×9 токенов) и на 1/8 после первой ступени декодера (192 канала, 4 головы, 38×18 токенов). Параметров ~6.94M; чекпоинты прежней архитектуры несовместимы.
- Метрика R в обоих ноутбуках — единый глобальный Пирсон по всем маскированным значениям эпохи (одна формула для train, val и test), а не среднее по батчам; накапливается на GPU через моменты (`new_r_moments`/`add_r_moments`/`r_from_moments`), синхронизация GPU→CPU один раз в конце эпохи. `correlation_r` остаётся для batch-R в потере и test-клетки.
- Аугментация только для train: положение патча, отражения и масштаб амплитуд генерируются динамически. Gaussian noise предрассчитывается при создании train-датасета в банк `NOISE_BANK_SIZE = 64`; пример использует шум по `index % 64`. `TRAIN_SAMPLES_PER_CENTER`: inpainting = 6, outpainting = 4; для inpainting явно заданы `VAL_SAMPLES_PER_CENTER = 8` и `TEST_SAMPLES_PER_CENTER = 4`, их выборки фиксированы.
- MLflow-трекинг в обоих ноутбуках: логируются параметры, LR, вес FFL, глобальные R и взвешенные вклады L1, MSE, R, gradient и FFL. Gradient norm и high-frequency удалены из логов. TensorBoard использует `runs/<task>/<timestamp>`, тест сохраняет модель через MLflow и завершает run.
- Held-out блок inpainting: `HELD_OUT_BOX = (77, 290, 179, 282)` (213×103 во всех срезах) исключён из train и как target, и как input: `make_inpainting_sample` отбрасывает патчи, пересекающие блок (`PATCH_REGIONS` — области, где остаётся хотя бы один допустимый патч), нормализация считается без блока. Validation и test (`held_out=True`) целиком состоят из дыры = этот блок, контекст — окружающие известные пиксели; положение патча варьируется (`y0 ∈ [2, 61]`, `z0 ∈ [154, 163]`, то есть дыра на `mask_z` 16–25, как на инференсе). Размеры датасетов не меняются. Блок должен быть известен во всех срезах и не пересекать реальную дыру; размеры должны совпадать с `MASK_H`×`MASK_W`.
- Разбиение: `inpainting.ipynb` — доли `TRAIN_RATIO`/`VAL_RATIO`/`TEST_RATIO = 0.88/0.08/0.04`, `SPLIT_GAP = 4`, `SLICE_RANGE = (2, 578)`; 500/45/23 центров и 3000/360/92 примеров для train/val/test; `outpainting.ipynb` — фиксированные центры (train 2–321, val 326–395, test 400–457) с защитными зазорами.
- Куб в обоих ноутбуках предзагружен в оперативную память (`np.load(DATA_PATH)`) вместо mmap: копирование патчей в датасете быстрее.
- В блоке тестирования обоих ноутбуков первая клетка загружает модель `UNet25D().to(device)` из чекпоинта (`best_inpainting_unet.pt` / `best_outpainting_unet.pt`): метрики и примеры предсказаний считаются на лучшей по валидационному R модели, а не на последней эпохе обучения; на всей тестовой маске считаются `test_loss` и глобальный `test_r` (TensorBoard `Loss/test`/`R/test`, MLflow `test_loss`/`test_r`).
- Инференс обоих ноутбуков — однопроходный: все пропущенные значения кодируются нулём и mask=1, как в обучении. В inpainting `predict_region` обрезает каждый из 5 кадров до 304×144 (`y=323:627`, `z=159:303`), с реальной дырой `y=45:258`, `z=20:123` внутри патча; предсказание записывается по локальной маске в полный куб. В outpainting модель применяется к полному срезу. `predict_frames`/`predict_region`: окно 5 кадров `index±2` через `np.clip` — несуществующие контекстные кадры на срезах 0, 1 и двух последних дублируют ближайший реальный кадр вместо нулей; каждый срез восстанавливается независимо, контекст — из исходного куба. Блок сохранения — один проход по всем срезам (tqdm `inference`); `restore_slice` (визуализация `slice_panels`/`show_restored_slice`) — тот же однопроходный расчёт.
- Детерминизм: `SEED=42` (random/np/torch/cuda). Оба ноутбука недетерминированы: `torch.backends.cudnn.benchmark = True` без `use_deterministic_algorithms` (разбег метрик между запусками ~1e-3); детерминизм `outpainting.ipynb` (`CUBLAS_WORKSPACE_CONFIG=:4096:8` + `use_deterministic_algorithms`) снят.

## Inference viewer
- `inference/serve.py` — автономный HTTP-сервер (stdlib + numpy, без других зависимостей): `python inference/serve.py --port N` → `http://127.0.0.1:N` (пути закреплены к корню проекта, не зависят от cwd). Автоскан `output/*/<task>_cube_restored.npy` (manifest живой — новые кубы появляются после обновления страницы без перезапуска). В RAM одновременно один куб (новый высвобождает старый, загрузка ~1–3 с); эндпоинты: `/` (index.html, читается с диска на каждый запрос), `/manifest` (JSON `{"cubes": [...]}`: shape, коробки пропусков, missed axis), `/slice?sub&task&axis&i` (uint8-плоскость, квантование p1–p99 по известным значениям куба). В manifest, кроме восстановленных, всегда два исходных куба `input_seismic_data/{inpainting,outpainting}_cube_missed_data.npy` (метка `label: «исходный»`, те же boxes/missed axis); серверятся через тот же `/slice` (в RAM по-прежнему один куб, исходные и восстановленные вытесняют друг друга).
- `inference/index.html` — просмотрчик: селектор куба (подпапка + задача), селектор оси (по умолчанию «ось пропусков»: inpainting→0, outpainting→1), слайдер среза (при смене оси/куба позиция сбрасывается туда, где пропуски видны: 0, если 0 внутри области пропусков, иначе середина первого интервала пропусков по оси), одна панель «Результат» (крупно) + подписи размерностей осей (ось K · M); область пропусков обведена красным контуром, в исходных кубах поверх — полупрозрачная подложка + штриховка + подпись «нет данных» (ноль пропусков квантуется в чёрный и сливался с фоном, поэтому выделен явно); пиксели панели записываются как `plane[x*h + y]` (x — ось `dims[0]`, y — `dims[1]`): прямое плоское копирование `plane[p]` давало сдвинутый (sheared) срез при различном размере двух осей; в селекторе кубов два «исходных» из `input_seismic_data` (в них пропуски нулевые — сравнение с результатом). Области пропусков заданы жёстко в `serve.py` (`TASKS`): inpainting `[:, 368:581, 179:282]`, outpainting `[:, 0:24, :]` + `[:, 457:481, :]`.
- `inference/README.md` — как запускать.

## Запуск и проверка
- Ноутбуки требуют входной `.npy` из `input_seismic_data/` и torch; вычислительное окружение — проект: `.venv` с torch 2.15.0+cu134 (CUDA, bf16), `python = .venv\Scripts\python.exe`; `torch.compile` требует triton — в venv стоит Windows-сборка `triton-windows` 3.9.0.post30 (wheel зеркалирован в `whl/`, офлайн-установка из `C:/Dev/offline_packages`).
- Скрипты проверки JSON/синтаксиса ячеек пишутся во временные `tmp_*.py` и удаляются после проверки.
- В кубах пропуски хранятся как 0 (NaN нет), поэтому проверка односторонняя: «область пропусков заполнена нулями». Вне области есть естественные нули (inpainting: 1 в (451, 363, 437), outpainting: 73), поэтому строгое сравнение `cube == 0` с маской не используется.
- `real_mask` в обоих ноутбуках строится in-place: 3D `np.zeros(cube.shape, dtype=bool)` — inpainting `[:, 368:581, 179:282]`, outpainting полосы `0:24` и `457:481`; маски из `.npy` не читаются. Геометрический кросс-чек в клетке инференса не зависит от формы `real_mask` (3D/4D): `mask_0 = real_mask[0, :, :, 0] if real_mask.ndim == 4 else real_mask[0]`.
